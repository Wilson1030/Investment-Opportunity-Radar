# 01 · 产品规格拆解

> 把原始规格（61 节 / 3094 行）转成**可执行、可验收**的需求条目。
> 每条带：来源章节 · 优先级 · 验收标准 · 落地位置。
>
> 优先级：**P0** = MVP 必须 · **P1** = MVP 之后第一批 · **P2** = 后续 · **P3** = 明确不做

---

## 0. 成功标准（来自 §56，不是功能而是效果）

| ID | 标准 | 验收方式 |
|---|---|---|
| S-01 | 用户每天打开后，**30 秒内**发现 1~3 个真正值得进一步研究的机会 | 自测：打开首页后计时，能否在 3 张卡内点开一张 |
| S-02 | 用户能在 **2 分钟内**理解「为什么这个机会值得关注，以及还有什么没确认」 | 自测：详情页首屏是否同时呈现「为什么现在」与「待确认事项」 |
| S-03 | ❌ 不以「支持多少只股票 / 多少 K 线指标 / 多少技术指标」衡量 | 任何以指标数量为卖点的设计一律驳回 |

> **S-01 与 S-02 是唯一的产品北极星。** 任何新功能都要回答：它让这两个时间变短了吗？

## M1 · 投资者画像（§4 / §5 / §6 / §36）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|:---:|---|
| M1-01 | 投资倾向采用「投资逻辑偏好」多选，而非「保守/稳健/激进」 | P0 | 画像配置页呈现 ≥20 个倾向项，全部可多选；无风险偏好三档控件 |
| M1-02 | 每个倾向可独立设权重（百分比），权重参与机会排序 | P0 | 改权重后首页排序发生变化；权重和不必为 100%（自动归一化） |
| M1-03 | 提供预设策略模板：重组猎手 / 困境反转 / 价值发现 / 成长投资 / 事件驱动 | P0 | 选中模板即写入一组预设倾向与权重 |
| M1-04 | 自然语言策略：用户描述 → AI 转结构化策略 YAML → **复述并向用户确认** | P1 | 输入规格 §6 的例句，输出含 market/stock_tags/financial_conditions/events/weights；必须先展示理解结果再执行 |
| M1-05 | 画像含投资周期、关注市场、行业偏好、排除条件 | P1 | 配置页可编辑并持久化 |
| M1-06 | 反馈闭环动态调整权重，**但必须允许用户手动覆盖** | P2 | 存在「AI 建议权重」与「用户锁定权重」两个字段；锁定后自动学习不生效 |

**关键约束**：同一个市场，不同用户看到**不同**的 Dashboard（§58 原则 6）。排序依据是 `Opportunity = Company × Profile × Thesis` 的组合，不是公司本身。

## M2 · 数据采集（§7 / §8 / §26 / §27 / §40 / §41 / §42）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|:---:|---|
| M2-01 | 接入公告数据（cninfo），覆盖 §7.2 列出的全部公告类型 | P0 | ≥25 种公告类型能被识别并归类；覆盖清单见 `06-策略设计总表` |
| M2-02 | 接入新闻（个股/行业/政策/财经媒体/机构观点） | P0 | 每条新闻保存：标题/来源/发布时间/原文链接/涉及公司/涉及行业/事件类型/情绪方向/可信度 |
| M2-03 | 接入财报结构化数据（非 PDF 存档） | P0 | 至少提取：收入/净利润/经营现金流/应收账款/毛利率/资产负债率及其同比 |
| M2-04 | 接入基础行情（价格/涨跌幅/成交量/市值/估值） | P0 | 仅作**辅助信息层**；严禁出现在首页主体 |
| M2-05 | 数据源抽象为可插拔 Adapter | P0 | 新增付费源只需实现 Adapter 接口，上层零修改 |
| M2-06 | 保留来源、时间、原始证据 | P0 | 每条数据有 `source_url` + `publication_time` |
| M2-07 | **区分「事件发生时间」与「系统发现时间」** | P0 | Event 表同时有 `event_time` 与 `discovery_time`，且不可混用 |
| M2-08 | 信息新鲜度展示（2小时前/1天前/…）与 New/Updated/Breaking/Stale 标记 | P1 | 卡片与事件流均显示相对时间 |
| M2-09 | 过时信息自动降权 | P1 | 超过阈值的信息在评分中衰减 |
| M2-10 | 新闻去重 → 聚类 → 事件化，输出 3~5 条要点而非 50 条新闻 | P1 | 27 条同主题新闻应聚成 1 个事件簇 + ≤5 条要点 |
| M2-11 | 财报事件化：不只展示数字，要输出「变化 → 原因 → 是否异常 → 可能逻辑」 | P1 | 例：「净利润下降」不得直接判为利空，需给出一次性费用/减值/周期等可能原因 |
| M2-12 | 交易日历 | P0 | 取不到时显式告警并退化为工作日判断 |
| M2-13 | 采集可观测：解析失败率、字段缺失率 | P0 | 每次采集输出统计，失败项可追溯（对应风险 R2） |

## M3 · 事件引擎（§9 / §10 / §31）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|:---:|---|
| M3-01 | 从新闻/公告/财报中识别事件，标准化为固定类型枚举 | P0 | 至少支持 §10 的 16 类：M&A / RESTRUCTURING / ASSET_INJECTION / CONTROL_CHANGE / SHAREHOLDER_BUY / SHAREHOLDER_SELL / BUYBACK / BANKRUPTCY_REORGANIZATION / EARNINGS_TURNAROUND / POLICY_CATALYST / MAJOR_CONTRACT / NEW_PRODUCT / MANAGEMENT_CHANGE / REGULATORY_RISK / LITIGATION（+ OTHER） |
| M3-02 | Event 字段完整：company / type / time / importance / certainty / source / summary / affected_thesis / evidence | P0 | 字段与 §10 YAML 一致 |
| M3-03 | 每条事件标注 `affected_thesis`（可能影响哪些投资逻辑） | P0 | 用于后续画像匹配 |
| M3-04 | `importance` 与 `certainty` 分别独立评分 | P0 | 「重要性高但确定性低」必须可表达（如市场传闻 vs 官方公告） |
| M3-05 | 事件与证据多对多关联 | P0 | 一条事件可引用多条 Evidence；一条 Evidence 可支撑多条事件 |

## M4 · 证据链（§15 / §16 / §32）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|:---:|---|
| M4-01 | 每个重要 AI 判断绑定 Evidence ID | P0 | `supporting_evidence` 必须为 Evidence ID 列表；无证据的判断不得标记为事实 |
| M4-02 | Evidence 记录 source / timestamp / original URL / document / **relevant paragraph** | P0 | 段落级定位：`relevant_text` + `page` + `para` 可跳转原文 |
| M4-03 | 证据可信度分级 A~E | P0 | A=正式公告/交易所披露 · B=财报官方文件 · C=高可信媒体 · D=机构研究观点 · E=社交媒体/市场讨论 |
| M4-04 | 重要逻辑尽量依赖 A/B 类证据；E 类只能作为「市场正在讨论什么」 | P0 | 若某 Thesis 的支撑证据中 A/B 类为空，前端强制标注「仅市场讨论，未经证实」 |
| M4-05 | 区分事实 / 推断 / 假设 / 市场讨论 | P0 | 展示层用不同视觉标记 |
| M4-06 | 无法确认时必须明说「尚未确认」，不得补全或猜测 | P0 | prompt 层强制；Schema 层用 `null` 而非占位值 |

## M5 · Thesis 引擎（§21 / §23 / §51 / §52 / §53）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|:---:|---|
| M5-01 | 用户关注的是「因为 X 逻辑，所以关注 Y」而非「自选股 Y」 | P0 | 存储对象是 Thesis，不是 Watchlist 条目 |
| M5-02 | Thesis 含 statement / thesis_type / supporting_evidence / invalidating_events | P0 | 字段与 §21 YAML 一致 |
| M5-03 | **每个 Thesis 必须定义失效条件** | P0 | `invalidating_events` 非空，否则不允许保存（§58 原则 5） |
| M5-04 | **Why Now 为固定字段** | P0 | 每个机会必须回答：过去 / 最近 / 本周 / 因此 |
| M5-05 | **Next Watch 为固定字段** | P0 | 必须列出下一步观察什么（如：重组方案公告 → 问询回复 → 资产评估 → 股东大会 → 审核） |

| M5-07 | 同一公司可对应多个 Thesis | P0 | 公司 K 可同时有「重组预期 95% / 困境反转 82% / 行业周期 76%」 |
| M5-08 | 同一事件对不同用户意义不同 | P0 | 回购事件：高股息用户 55% · 股东回报用户 94% · 重组用户 18%（§5.8） |
| M5-09 | 10 类 Thesis 统一字段设计 | P0 | 见 `06-策略设计总表.md` |

## M6 · 机会引擎与评分（§11~§14 / §37 / §38）

| ID | 需求 | 优先级 | 验收标准 |
|---|---|:---:|---|
| M6-01 | 机会 = **公司 × 投资者画像 × Thesis** 的组合 | P0 | Opportunity 表同时有 `company_id` / `profile_id` / `thesis_id` |
| M6-02 | 不输出单一神秘总分，展示多维评分 | P0 | 至少 6 维：事件催化 / 逻辑匹配 / 确定性 / 市场关注 / 基本面 / 风险 |
| M6-03 | 评分可点击展开**逐项加减分明细**，每项绑定证据 | P0 | 例：`+25 存在重大资产重组公告(A级)` · `-10 重组方案尚未确定` |
| M6-04 | 规则分为主分，LLM 分为辅分，分歧 >20 标红 | P0 | 见 D08 |
| M6-05 | 排序基于 `Event Strength × Thesis Match × Evidence Quality × Certainty − Risk` | P0 | MVP 用规则加权，后期再学习 |
| M6-06 | 允许出现「高匹配 + 高风险」 | P0 | `Match 94 / Opportunity 82 / Risk 78` 必须能同时展示 |
| M6-07 | 「高匹配」≠「高收益」，系统不得暗示收益 | P0 | 文案审查：全站无收益承诺类表述 |
| M6-08 | 候选池漏斗 5000+ → 300 → 80 → 20 → 5~10 | P0 | 每级漏斗有日志计数；LLM 只处理最后一级 |

## M11 · AI 治理与输出规范（§13 / §25 / §28 / §39 / §50 / §51）

| ID | 需求 | 优先级 | 验收标准 |
