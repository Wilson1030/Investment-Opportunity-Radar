| 形态 | 本地单用户；表结构预留 `user_id`；**明确不做 SaaS** |

## 4. 已修复的 bug 清单（★ 每个都带教训，避免重犯）

### 4.1 数据正确性

| # | Bug | 教训 |
|:---:|---|---|
| 1 | **证据链整体错位到别的公司** —— `ConditionResult.evidence_ids` 里装的是 `Event.id` | **错误 ID 与正确 ID 都「查得到」时，只有「归属校验」能区分**。跨表引用必须校验归属 |
| 2 | 「跳转原文」不带页码锚点 → 永远停在 PDF 第 1 页 | 先分清是「链接错」还是「定位不定位」；数据与链接可能都是对的 |
| 3 | 失效规则**完全没覆盖** `BANKRUPTCY_REORGANIZATION` → 死掉的苗头永远挂着 | 漏掉是不作为，**挂着不放是主动误导** |
| 4 | 催化阶梯与失效规则**各写一份关键词表** → 漂移 | **同一判断有两份实现，就一定会漂移** |
| 5 | `tools/reset_db.py` 自己拼数据库路径 → 清库清了另一个文件 | 同上：**同一事实两个来源必漂移** |
| 6 | 相对 SQLite 路径按 CWD 解析 → **静默产生两个数据库** | 相对路径必须显式解析为绝对 |
| 7 | 失效事件被当成正向催化（终止公告照拿 +40）→ 逻辑已失效但分数只掉 2 分 | 分数必须与状态一致 |

### 4.2 功能被做坏 / 做偏

| # | Bug | 教训 |
|:---:|---|---|
| 8 | **5 个 AI 节点里只有 1 个被调用** → 卡片的「AI 判断」全空 | 写了不等于接上了。**要端到端验证，不是验证组件存在** |
| 9 | 思考型模型的推理 token 吃掉输出上限 → `raw_output` 长度为 0 | qwen3 的 thinking 也计入 `num_predict` |
| 10 | 只给 `format:"json"` 不约束字段 → 小模型**复读输入**（6/6 失败） | 要用**结构化输出**（把 Schema 传给 `format`） |
| 11 | 输出上限设 900 → JSON 被截断（5/5 失败） | 安全阀不能压到正常输出 |
| 12 | `.env.example` 写了 config 不存在的变量 | 用户照配**不生效且无报错** → 加测试校验 |
| 13 | `LLM_MODE=dev` 静默覆盖用户显式配置的 provider | 配置被静默忽略最难查 |

### 4.3 验证方法本身出错（最值得记）

| # | 问题 | 教训 |
|:---:|---|---|
| 14 | 用 **mock 源**「验证」并发等价 —— 而 mock 根本不走缓存 | **验证必须真的走到被测路径上**。那种绿色比红色更危险 |
| 15 | 只写「上限确实传进请求体」的测试，**从未验证真实抽取仍成功** | **验证机制 ≠ 验证结果** |
| 16 | 测试期望值**随日历漂移**（mock 用绝对日期 + 衰减用真实时钟） | 这种测试比没有测试更糟 |
| 17 | 基于「250 秒/条」优化了三轮 —— 而那个数字是**我自己并发跑诊断命令抢 GPU** 造成的 | **先建立可信的测量，再优化** |
