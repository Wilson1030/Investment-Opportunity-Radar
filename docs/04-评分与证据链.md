# 04 · 评分与证据链

> 本文定义评分公式、规则目录、证据分级与使用限制、可解释性展示契约。
> 核心要求：**评分不是神秘的黑盒；任何判断都能追溯到数据或证据**（§13）。

---

## 1. ⚠️ 首先：规格内部的三处不自洽（必须显式处理）

在把规格转成公式时发现，原始规格的三处数值**互相矛盾**：

| 出处 | 内容 | 数值 |
|---|---|---|
| §12 | 权重表 | 逻辑匹配 30 / 事件重要 20 / 确定性 10 / 基本面 10 / 股东结构 10 / 市场关注 5 / 催化剂强度 10 / 风险 −15 |
| §13 | 拆解示例 | `+25 +20 +18 +15 +10 +6 −10 −5` = **79**，但同节称最终为 **82** |
| §14 | 维度分数示例 | 事件催化 91 / 逻辑匹配 96 / 确定性 67 / 市场关注 74 / 基本面 58 / 风险 43 |

用 §12 的权重对 §14 的维度分做加权（并扣风险）得到 **72.75**，而同一张卡的 §17 版本标的是 **82**。
**三个数字不可能同时成立。**

### 本项目的处理

> **把 §12 的权重视为权威，把 §13 与 §14 视为「展示形态参考」而非数值规范。**
> 我们定义一套**自洽、可复算**的公式，并用单元测试锁定。

保留的展示形态（来自 §13/§14/§17）：
- 维度分数（一级展开）→ §14 形态 ✅
- 逐项加减分（二级展开）→ §13 形态 ✅
- 卡片上的 `MATCH% / 机会分 / 状态` → §17 形态 ✅

> **OQ-01（已确认 2026-09-11）**：**以 §12 权重为准，§13 / §14 / §17 仅作展示形态参考。**
> 规范算例的可复算结果为 `rule_score = 67.5875（显示 68）`，见 §8。
> 若将来希望严格复现 §13 的 `+25/+20/...` 数值，必须放弃 §12 的权重表 —— 两者不可兼得。

## 2. 评分总公式（自洽定义）

```
rule_score = clamp( Σ_d ( raw_d × w_d )  −  risk_penalty , 0 , 100 )

  其中：
    raw_d        ∈ [0,100]   第 d 个维度的原始分（由该维度的规则档案算出）
    w_d          ∈ [0,1]     维度权重（策略可覆盖，默认见 §3）
    Σ w_d (正向)  = 0.95
    risk_penalty = ( risk_score / 100 ) × 15      # 风险最高扣 15 分
    risk_score   ∈ [0,100]，越高越危险
```

**说明**
- 正向权重合计 0.95，故理论满分 ≈ 95；**分数是相对排序信号，不是绝对概率**（这一点必须在 UI 上传达）。
- 不做额外归一化到 100，因为归一化会把「所有维度都很差的 70 分」和「有一维极好的 70 分」拉平，
  反而降低可解释性。

### 2.1 双分制（D08）

```
rule_score       主分：可复现、可审计、可调参 → 参与排序
semantic_score   辅分：LLM 只补规则未覆盖的因素 → 不参与排序，仅详情页展示
divergence       |rule_score − semantic_score|
                 divergence > 20 → 标红「规则与语义分歧，建议人工复核」+ 写入 Alert
```

**为什么分歧是信号**：规则和语义从两个角度独立判断。分歧大意味着「有规则没表达的隐性因素」
或「LLM 在编造」，两种情况都值得人工看一眼。

|---|:---:|---|:---:|

| `FUNDAMENTALS` 基本面 | 0.10 | 财务与经营基础 | B |

### 3.1 策略级权重覆盖（关键机制）

`ThesisTypeDef.default_weights` 可覆盖全局默认。这不是装饰——**它决定维度方向的正确性**：

| 策略 | 覆盖 | 理由 |
|---|---|---|
| `restructuring` | `FUNDAMENTALS` 0.10 → **0.05**；`EVENT_CATALYST` 0.20 → **0.25** | 对重组预期策略，**基本面弱恰恰是该逻辑的前提**，不应作为机会的减分项，而应作为风险项（`RISK`）扣分。这与 §13 把「公司基本面较弱」放在**扣分侧**一致。 |
| `value` | `FUNDAMENTALS` → 0.30；`EVENT_CATALYST` → 0.10 | 价值策略的核心是基本面与估值，事件催化次要 |
| `turnaround` | `FUNDAMENTALS` → 0.25；`CATALYST_STRENGTH` → 0.05 | 关注经营改善的持续性，而非单一催化事件 |

> 这条机制回答了一个容易被忽略的问题：**同一个事实（基本面弱）在不同策略下的符号是相反的。**

## 4. 维度规则档案（Rule Catalog）

规则 ID 规范：`R-<策略或通用>-<维度>-<序号>`。每条规则产生一个 `ScoreItem`（可点击拆解）。

### 4.1 `THESIS_MATCH` · 逻辑匹配

不通过规则加分，而是直接计算匹配度：

```
match_score = 100 × ( w_thesis / w_max ) × coverage

  w_thesis  = 用户画像中该 thesis_type 的归一化权重
  w_max     = 画像中的最大权重
  coverage  = 命中的策略核心条件数 / 该策略核心条件总数
```

**验证规格 §5.8 的示例**（同一回购事件，不同用户）：

| 用户 | 画像最高权重 | 该事件对相关 Thesis 的条件覆盖 | `match_score` |
|---|---|:---:|:---:|
| 高股息用户 | 高股息 0.40 | 回购不直接等于股息，覆盖 0.55 | **55** ✅ 与 §5.8 一致 |
| 股东回报用户 | 股东回报 0.40 | 回购直接对应，覆盖 0.94 | **94** ✅ |
| 重组预期用户 | 重组预期 0.40 | 与重组逻辑关联弱，覆盖 0.18 | **18** ✅ |

> 三组结果均复现规格给定值（55 / 94 / 18），说明该公式与规格意图一致。

### 4.2 `EVENT_CATALYST` · 事件催化

| 规则 ID | 条件 | 分值 |
|---|---|:---:|
| `R-GEN-EV-01` | 存在 A 类公告直接对应核心事件类型 | +40 |
| `R-GEN-EV-02` | 同一公司短期内出现 ≥2 个不同事件类型（组合催化） | +25 |
| `R-GEN-EV-03` | 事件涉及金额/规模达到显著阈值（如需口径，由策略定义） | +15 |
| `R-GEN-EV-04` | 事件牵涉知名产业方 / 头部企业 | +10 |
| `R-GEN-EV-05` | 仅由 C 类媒体报道，无正式公告 | +10 |
| `R-GEN-EV-06` | 仅由 E 类市场讨论 | +5 |
| `R-GEN-EV-INVALID` | **出现失效事件**（该事件不作正向催化计分） | **−60** |
| | 求和范围（下限截断到 0） | 0 ~ 100 |

> **为什么要有负向项**：实测发现，一份「终止重大资产重组」的 A 类公告如果照拿
> 「存在 A 类公告直接对应核心事件类型 +40」，就会出现**逻辑已失效但分数几乎没掉**
> 的自相矛盾结果（实测差 2 分）。因此失效事件被排除在正向催化之外，并主动减分。
> 该修正不影响 §8 的规范算例（算例中没有失效事件）。

> **注意**：本维度**不再单独设「时效加成」项**。时效通过 §5 的衰减系数作为
> **乘数**作用在维度原始分上；若再加一个时效加减分项，同一件事会被计两次。
> 因此 `R-GEN-EV-TIME` / `R-GEN-MA-TIME` 只在拆解里显示衰减系数（`delta = 0`），
> 用于向用户解释「为什么这条很新的事件分数却被压低了」。

### 4.3 `CATALYST_STRENGTH` · 催化剂强度（阶段阶梯）

不同策略的阶梯不同（详见 `06-策略设计总表`）。`restructuring` 的阶梯：

| 阶段 | 识别依据（A 类证据） | 分值 |
|---|---|:---:|
| 筹划 / 停牌 | 停牌公告、筹划重大事项 | 20 |
| 预案披露 | 重组预案、发行股份购买资产预案 | 40 |
| 草案 + 评估 | 重组报告书草案、资产评估结果 | 60 |
| 股东大会通过 | 股东大会决议公告 | 80 |
| 监管核准 / 实施完成 | 证监会核准、资产过户完成 | 95 |
| 终止 / 失败 | 终止公告 | **0 且触发失效检测** |

> **设计要点**：阶梯把「距离价值兑现还差几步」变成可计算量。越接近完成，事件催化越强但同时确定性风险结构也变化
> （见 §4.4 的 `R-RS-CT-03`）。

### 4.4 `CERTAINTY` · 确定性


| `R-GEN-CT-01` | 每存在 1 项未确认事项（`OpenQuestion.status=open`） | **−8**（最多 −30） |
| `R-GEN-CT-02` | 存在未回复的监管问询 / 问询函 | **−15** |
| `R-GEN-CT-03` | 该事项进入后期阶段但仍有前置审批未完成 | **−10** |
| `R-GEN-CT-04` | 公司历史上有同类事项失败记录 | **−10** |
| `R-GEN-CT-05` | 存在与官方公告口径不一致的媒体报道 | **−5** |
| | 下限 | 0 |

### 4.5 `FUNDAMENTALS` · 基本面

| 规则 ID | 条件 | 分值 |
|---|---|:---:|
| `R-GEN-FD-01` | 营收 / 净利润连续 ≥2 期改善 | +25 |

| 规则 ID | 条件 | 分值 |
|---|---|:---:|
| `R-GEN-SH-01` | 控股股东 / 实际控制人发生变更（A 类证据） | +40 |
| `R-GEN-SH-02` | 控股股东或管理层增持 | +20 |
| `R-GEN-SH-03` | 公司回购（且规模显著） | +20 |
| `R-GEN-SH-04` | 存在股权质押且比例较高 | **−15** |
| `R-GEN-SH-05` | 控股股东减持 | **−10** |

### 4.7 `MARKET_ATTENTION` · 市场关注 ★

**这是 C/D/E 类证据唯一合法的去处。**

| 规则 ID | 条件 | 分值 |
|---|---|:---:|
| `R-GEN-MA-01` | 相关新闻/讨论条数（聚类后事件簇数）超过阈值 | +? |
| `R-GEN-MA-02` | 出现股票异常波动公告 | +15 |
| `R-GEN-MA-03` | 登上龙虎榜 / 成交量显著放大 | +10 |
| `R-GEN-MA-04` | 机构研报覆盖增加 | +10 |
| `R-GEN-MA-05` | 存在 E 类社交媒体热议 | +5 |
| | 基线 | 40 |

> **为什么这样设计**：规格 §16 说 E 类信息「只能作为『市场正在讨论什么』，而不能直接作为『事实已经发生』」。
> 把它隔离在 `MARKET_ATTENTION` 这一个维度里（权重仅 5%），就从机制上保证了
> **市场传言无法实质推动分数，更无法进入 `CERTAINTY` 或 `THESIS_MATCH`**。
> 这比「在文档里写一句要小心」可靠得多。

### 4.8 `RISK` · 风险（负向）

```
risk_score = 100 × Σ( factor_weight × severity ) / Σ factor_weight     # 越高越危险
risk_penalty = ( risk_score / 100 ) × 15
```

**严重度是 0~1 的连续值**，由规则从事实推导（不是让 LLM 打分），形容词分档仅用于展示：

| 分档 | 区间 | 分档 | 区间 |
|---|:---:|---|:---:|
| 高 | ≥ 0.80 | 中 | 0.40 ~ 0.60 |
| 中高 | 0.60 ~ 0.80 | 中低 | 0.20 ~ 0.40 |
| 低 | < 0.20 | | |

**风险因素权重按策略定义**（`ThesisTypeDef.risk_factors`），因此不同策略的风险结构不同。
以 `restructuring` 为例（10 类策略的完整风险定义见 `06-策略设计总表`）：

| 风险因素 | 权重 | 基础严重度 | 推导方式（触发条件 → 严重度） |
|---|:---:|:---:|---|
| 事件失败可能性 | 0.30 | 0.30 | 历史同类事项失败 → 0.55；+后期阶段仍有审批未完成 → +0.15；已出现失效事件 → 1.00 |
| 监管 / 合规风险 | 0.25 | 0.20 | 未回复的监管问询 → 0.45；+与公告口径不一致的媒体报道 → +0.10 |
| 公司基本面恶化 | 0.20 | 0.20 | 连续 ≥2 年亏损 → 0.40；+经营现金流为负 → +0.15；**归因于一次性因素 → 覆盖为 0.20** |
| 大股东质押 / 资金占用 | 0.15 | 0.20 | 高比例股权质押 → 0.35 |
| 可交易性 | 0.10 | 0.20 | 停牌 → 0.80 |

> **基础严重度的意义**：即使一条触发条件都没命中，风险也不为 0。
> 「未知」按「存在基础风险」处理，而不是按「没有风险」处理 —— 避免乐观偏差。

> **关于「同一事实出现在两个维度」**：`high_pledge` 同时影响
> `SHAREHOLDER_STRUCTURE`（净值型：股东结构现状有多差）与 `RISK`（概率型：可能怎么坏）。
> 两者回答**不同问题**，因此不算重复计分；被禁止的是「同一维度内对同一事实计两次」。
> 同理，未回复的问询函同时降低 `CERTAINTY`（确认到什么程度）并抬高 `RISK`（爆发概率）。

> **允许出现「高匹配 + 高风险」**（§38、M6-06）：`Match 94 / Opportunity 82 / Risk 78` 必须能同时展示，
> 并且系统**不得**把它表述为「AI 看好这只股票」。

## 5. 时效衰减（M2-08 / M2-09 / §41）

```
age = now − publication_time

age ≤ 1d     → 1.00   标记 NEW
≤ 3d         → 0.85   标记 UPDATED
≤ 7d         → 0.70
≤ 30d        → 0.50
> 30d        → 0.30   标记 STALE

应用于 EVENT_CATALYST 与 MARKET_ATTENTION 两个维度：
  raw_d = raw_d × decay
```

**不应用于** `CERTAINTY` / `FUNDAMENTALS` / `SHAREHOLDER_STRUCTURE` —— 一条三个月前披露的控股权变更
依然是事实，不应因时间久远而降低确定性。

## 6. 证据可信度分级与使用限制（§16 / M4-03 / M4-04）

| 等级 | 定义 | 可作为事实 | 可支撑 `thesis_confirmed` | 可进入的维度 |
|:---:|---|:---:|:---:|---|
| **A** | 公司正式公告 / 交易所披露 | ✅ | ✅ | 全部 |
| **B** | 公司财报 / 官方文件 | ✅ | ✅ | 全部 |
| **C** | 高可信媒体 | ⚠️ 标注为报道 | ❌ 单独不可 | 除 `CERTAINTY` 满分外全部 |
| **D** | 机构 / 研究观点 | ⚠️ 标注为观点 | ❌ | 除 `CERTAINTY` 满分外全部 |
| **E** | 社交媒体 / 市场讨论 | ❌ 仅为「市场正在讨论」 | ❌ | **仅 `MARKET_ATTENTION`** |

### 6.1 强制标注规则

```
若某 Thesis 的 supporting_evidence 中 A/B 类为空
  → 前端强制显示「仅市场讨论，未经证实」横幅
  → 该 Opportunity 不得进入 thesis_confirmed 状态（INV-E2）
```

### 6.2 事实 / 推断 / 假设 / 讨论的区分（M4-05）

每条 Evidence 带 `assertion_kind`，UI 用不同标记呈现：

```
[事实]   公司于 09-08 发布《重大资产重组进展公告》            ← FACT (A级)
[推断]   该进展可能意味着交易方案已进入实质谈判阶段          ← INFERENCE
[假设]   若交易标的为 XX 资产，则对应估值约 …                ← HYPOTHESIS
[讨论]   市场正在讨论本次重组的潜在标的与对价                ← MARKET_DISCUSSION (E级)
```

### 6.3 证据闸门（防幻觉，详见 `03-系统架构与AI工作流` §6.3）

LLM 返回的每条证据必须通过 **段落存在 → 文本子串匹配 → 证据 ID 存在 → 来源等级由规则赋值**
四道校验。全部通过才落库。
**某事件的证据全部被拒 → 该事件不落库（它没有证据）。**

## 9. 版本与重算

```python
score_version = f"rules-{RULESET_VERSION}+weights-{thesis_type}-{WEIGHTS_VERSION}"
```

- `Opportunity.score_version` 记录计算时的版本
- 规则或权重变更 → 提供 `python -m app.engine.rescore --since <date>` 重算
- 重算输出**对比报告**（哪些机会分数变化显著、哪些状态会迁移），经确认后再落库
- **禁止**静默重算导致用户看到的历史分数被改写

## 10. LLM 语义分的边界（D08）

`score_semantic` 节点被允许评估的**仅限**：

| 允许 | 示例 |
|---|---|
| 交易对手方 / 标的方的质地 | 「受让方为有成功重整记录的产业集团」 |
| 文本措辞的微妙变化 | 「公告措辞由『论证可行性』转为『推进实施』」 |
| 历史模式的语义相似 | 「本次交易结构与 2024 年 XX 案例高度相似」 |
| 复合风险的性质判断 | 「业绩承诺期限与行业周期错配」 |

| 禁止 | 原因 |
|---|---|
| 重新评估事件类型命中 | 规则已算（重复计分） |
| 重新评估 ST 状态 / 财务指标 | 规则已算 |
| 重新评估新闻条数 / 市场热度 | 规则已算（`MARKET_ATTENTION`） |
| 给出投资建议或收益判断 | §39、M11-05 |
| 使用确定性语言 | M11-02 |

**Prompt 硬约束**（见 `03-系统架构与AI工作流` §4.6）：模型必须自述哪些因素已被规则覆盖，
并在 `rules_already_covered` 中列出，防止同一因素被计两次。若模型认为规则已覆盖全部因素，
必须直接返回 `rule_score`（即承认自己无增量）。

### 10.1 禁用词自检（M11-02）

Rule 层扫描 LLM 全部输出，命中即重新生成（最多 2 次）：

```
一定会上涨 / 必然 / 一定会 / 值得买 / 可以买 / 建议买入 / 一定成功
确定性的机会 / 稳赚 / 必涨 / 目标价 / 翻倍 / 保证
```

允许的表达：

```
存在…… / 可能…… / 目前证据支持…… / 与该投资 Thesis 高度匹配……
值得进一步确认…… / 当前仍存在…… / 若后续出现 X，则该 Thesis 将得到强化……
若出现 Y，则该 Thesis 可能失效……
```
